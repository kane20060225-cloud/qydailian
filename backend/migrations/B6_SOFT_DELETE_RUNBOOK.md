# B6.3 租号账号软删除与索引

此批在“我的出租”和“管理面板 → 租号审核”增加删除、已删除筛选与恢复。
删除是 `deleted_at` 标记加状态下架，不执行 SQL `DELETE`，不会清除账号资料、
审核审计、出租收益或历史租单。恢复回到 `pending`，必须重新审核才能上架。
有 `pending`/`active` 租单时拒绝删除。所有状态变更与 B5 操作审计同事务。

## 生产迁移的前置条件

生产库目前缺少 `rental_accounts.deleted_at`，因此**不能先部署本批运行代码**。
须得到单独生产 DDL 授权，先核对线上代码哈希、表结构、现有索引和租单状态，
做新鲜受限备份，再对迁移执行只读计划、隔离测试和加法迁移。迁移只包含：

1. `rental_accounts.deleted_at DATETIME NULL`；所有旧记录默认为 NULL。
2. 账号可见列表及出租方列表的复合索引各一个。
3. `rental_orders(account_id, status)` 占用检测索引一个。

迁移命令默认拒绝隐式执行：`npm run migration:b6:rental --prefix backend -- --plan`。
显式 `--apply` 还要求 `--confirm=B6-RENTAL-ADDITIVE-MIGRATION`，并须先获
得独立生产授权。不要显示、复制或提交 `.env` 中的密码和密钥。

## 部署与验收

- 加法迁移后只读确认字段与索引结构，再部署与仓库哈希一致的白名单代码文件；
  不覆盖 `.env`、支付宝密钥、上传目录及 `node_modules`。
- 在隔离目录和本地跑全量合成凭据测试、语法检查；重启 PM2 后检查健康接口。
- 管理员与出租方分别尝试删除无租单账号、查看已删除、恢复为待审核；
  另用两账户测试进行中租单被拒绝删除。不要替用户自动审核或创建真实订单。
- 默认审核列表和公开大厅均须隐藏已删除记录，公开详情须 404，历史租单查询
  仍须能关联原账号。

## 回滚限制

若上线后尚无删除动作，可只恢复本批运行代码并重启 PM2；新增列与索引可保留，
不做 `DROP`。一旦已有删除动作，旧版代码不识别 `deleted_at`，可能让管理员重新
上架隐藏账号。此时须先评估业务状态，不能直接退回不识别软删除的旧版，也不
能通过 SQL 自动反向清空删除标记。
