# B14 未付款取消、24小时超时关闭及历史充值核销

此版本新增两张元数据表，不自动回填、删除历史订单或改变余额。上线必须先完成 B5、B9、B11，然后执行 B14 增量迁移，再发布本次后端和前端文件；旧版代码可继续使用这两张新增表。

## 发布

在已配置正确数据库的 backend 目录执行：

```powershell
npm run migration:b14:lifecycle -- --plan
npm run migration:b14:lifecycle -- --apply --confirm=B14-ORDER-LIFECYCLE-ADDITIVE-MIGRATION
npm run migration:b14:lifecycle -- --plan
```

迁移验证字段、主键、校验和及迁移锁，只允许新增 `recharge_order_resolutions`、`order_lifecycle_settings`。默认超时关闭未启用，不会在发布后立刻处理旧单。应先备份数据库，并在隔离库验证后发布。未迁移 B14 就部署新代码，会导致订单中心查询失败。

## 使用

- 未付款代练／租号详情：点击“取消未付款订单”，填写原因。仅允许客户本人或管理员操作；源订单加锁，未接单、未执行、没有付款审核或任何付款凭证才可取消。仅匹配原始扣减流水退回积分；历史租单抵扣缺少匹配流水、其他资金流水、收退款及结算记录全部保留待人工核对。重复请求不会再次退款。已关闭代练不能再上传凭证或确认收款。
- 管理员订单中心：“24小时超时关闭”先预览。可以单次关闭本次预览中的订单，也可以保存独立开关启用每小时自动检查。自动检查也处理符合条件的历史订单，最多扫描200个候选项；每单在事务内重新检查，不处理已在回收站的订单。关闭与移入回收站独立；含退款流水的订单可归档或软删除，但不会永久清理其资金记录。
- “到账待核对／到账处理中”充值详情：“核销历史到账异常”。必填原因、核对依据，并勾选已核对付款与发券记录。核对依据不能包含密码、密钥或完整账户凭据。
  - `test_closed`：确认无真实付款且从未发券，登记核销关闭，不修改原支付状态或余额。有已知成功支付记录不允许；支付已启用时也查询支付宝，存在成功或未关闭交易会拦截。保留原始支付记录和审计信息，可归档或软删除，不永久删除原已支付测试记录。
  - `historical_credited`：只允许历史本地已支付、无对应资金流水的订单。人工确认已发券后登记已到账；不改变余额，不伪造到账流水或历史到账时间。支付服务可用时检查交易号、金额和平台结果；没有可用平台结果时，需人工提供实际核对依据。
  - `tickets_backfilled`：确认真实支付成功且从未发券后补发。必须启用支付宝，并通过签名验证的实时查询确认支付成功，金额和已有交易号必须匹配。数量取充值快照，旧单默认10000券。采用与正常通知相同的唯一到账键 `payment:<订单号>:tickets_credited`，余额、流水、支付状态、核销记录与审计在同一事务内提交。

无法确认是否发过券时，不选择“补发”或“无付款测试单”。测试时期发过券、存在其他流水的订单不能冒充无付款未发券订单核销；保留其异常直到按实际记录另行处理。

核销结果与原状态、交易号快照关联。测试核销后收到支付成功观测，或原支付状态／交易号变化时，旧核销不再遮盖异常。允许对已失效的核销重新逐笔核对，审计保留前次操作。已生效核销不能重复执行。

## 验证与回滚

```powershell
npm test
node scripts/verify-order-lifecycle-browser.js
node scripts/verify-order-lifecycle-isolated.js --database=qydailian_b14_test_<suffix>
```

浏览器验证需要 Playwright 和已安装的 Chromium／Edge，可设置 `BROWSER_CHANNEL=msedge`。使用本地合成订单和 API，不读取生产 .env、不访问真实支付、不修改真实订单。单元及接口测试覆盖权限、并发重复退款／补发、原流水匹配、事务失败回滚和历史已到账不修改余额。

本地没有真实 MySQL／支付宝配置时，不能将合成测试视为真实数据库或支付验收。B9、B11 隔离验证脚本已经纳入 B14 迁移；只允许显式命名的空测试库。

回滚前关闭超时开关，再恢复旧前后端文件，保留新增表、已提交退款／补发流水及核销审计。旧代码可能重新显示历史充值异常，不能通过删除流水或改余额掩盖。未处理的订单数据不会被迁移改变。
