# B6.5 租号截图流式上传

新出租申请的 PNG/JPEG 截图改为浏览器直接发送图片请求体，后端通过异步
pipeline 写入随机 `.part` 临时文件，验证 5MB 上限及文件头后原子改名。异常、
超限或伪造图片都会清理临时文件，不再将新截图转 Base64 JSON，也不再使用
同步 `writeFileSync` 阻塞事件循环。

旧版页面以及租号付款凭证仍可能提交 Base64 JSON；后端保留兼容入口，但它们
也经过同一异步大小和文件头校验。新 JPEG 使用 `.jpg`，安全文件名和 B5 付款
凭证校验同时支持既有 `.png` 及 `.jpg/.jpeg`。本批不移动或修改已有上传文件，
不改数据库、支付、租单状态及支付宝配置。

部署时须先核对线上文件哈希并制作新鲜应用备份，在无生产 `.env` 的隔离目录
运行全量测试和语法检查。白名单文件包括后端入口、上传模块、前端租号客户端
和主脚本；不得覆盖生产 `.env`、密钥、`uploads` 或 `node_modules`。部署后重启
PM2，检查健康接口、静态新模块、匿名权限，并由用户使用非敏感测试图片分别
试传 PNG/JPEG。不要自动创建真实订单或提交付款凭证。

若上传异常，从本批应用备份恢复代码并重启 PM2；本批没有 DDL 或数据回滚。
已成功上传的图片不因代码回滚而自动删除，避免误删仍被申请或付款证据引用的
文件。
