# B4 会话失效迁移手册

本批次不修改支付配置或支付数据。B3 真实付款验收前，不建议部署 B4 生产版本。

二次认证阶段另需 `20260915_b4_totp.sql`。先在隔离测试数据库完成迁移和 TOTP 登录、绑定、关闭验收。迁移前核查旧版 `two_factor_enabled=1` 行数量；旧页面曾允许只修改开关，此类账户必须人工处理，不能盲目清空密钥或批量关闭。迁移只扩大密钥列并新增防重放时间步，不删除数据。

绑定密钥使用现有 `DATA_ENCRYPTION_KEY` 加密；在失去该密钥时，已启用二次认证的账户无法登录。部署前确认该密钥已有安全备份，切勿写入文档、日志或 Git。验证服务器时间同步，避免验证码校验错误。恢复部署时要同时考虑字段和代码版本；不要直接回缩密钥列，避免截断已加密密钥。

当前登录失败限制是单 Node 进程内的 15 分钟/5 次策略。若 PM2 开启多实例、反向代理更换 IP 标识或需跨重启生效，应先配置共享限流/网关防护再开放二次认证。用户遗失身份验证器时目前没有自动恢复流程，只能经人工核验后另行制定安全恢复方案，不能直接清空生产密钥。

## 实施顺序

1. 备份并核验生产应用与用户表。
2. 只读确认 `users.token_version` 尚不存在，并确认线上代码与 B3 基线一致。
3. 在维护窗口执行 `20260915_b4_token_version.sql`，只新增整数列，默认值为 0。
4. 在 staging 用模拟用户验证登录、退出、改密码、旧 JWT 拒绝和管理员权限。
5. 部署 B4 代码，验证新 JWT 可使用，旧 JWT 被拒绝。现有用户需要重新登录一次。
6. 退出登录会使该账号的所有设备会话失效；改密码会失效旧会话并向当前浏览器签发新 JWT。

## 回滚边界

- 新增列保留，不执行 `DROP COLUMN`。
- 回滚到 B3 后，B3 代码不会检查 `token_version`；需先暂停认证入口并评估旧 JWT 风险，不可直接无审核回滚。
- 本批次不启用尚未实现的二次认证；以后如要实现 2FA，须独立设计密钥、恢复码和完整登录验证流程。
