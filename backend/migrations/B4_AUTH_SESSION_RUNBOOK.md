# B4 会话失效迁移手册

本批次不修改支付配置或支付数据。B3 真实付款验收尚未完成，B4 上线后的支付回归仍需等待限额调整完成。

二次认证阶段另需 `20260915_b4_totp.sql`。先在隔离测试数据库完成迁移和 TOTP 登录、绑定、恢复码登录、关闭验收。迁移前核查旧版 `two_factor_enabled=1` 行数量；旧页面曾允许只修改开关，此类账户必须人工处理，不能盲目清空密钥或批量关闭。迁移只扩大密钥列、新增防重放时间步和恢复码表，不删除数据。

绑定密钥使用现有 `DATA_ENCRYPTION_KEY` 加密；在失去该密钥时，已启用二次认证的账户无法登录。部署前确认该密钥已有安全备份，切勿写入文档、日志或 Git。验证服务器时间同步，避免验证码校验错误。恢复部署时要同时考虑字段和代码版本；不要直接回缩密钥列，避免截断已加密密钥。

当前登录失败限制是单 Node 进程内的 15 分钟/5 次策略。若 PM2 开启多实例、反向代理更换 IP 标识或需跨重启生效，应先配置共享限流/网关防护再开放二次认证。启用时一次性显示 8 个恢复码，服务器仅保存高熵恢复码哈希，使用后标为失效。用户同时遗失身份验证器和恢复码时，仍只能经人工核验后另行制定安全恢复方案，不能直接清空生产密钥。

生产节点同时监听 80/443 的 Nginx 和 3000 的 Node。应用仅信任本机代理提供的真实 IP；应人工确认阿里云安全组和主机防火墙未将 3000 端口向公网开放。不得在没有核查的情况下相信任意外部 `X-Forwarded-For`。

## 实施顺序

1. 备份并校验新鲜的生产数据库、应用文件和敏感配置；备份仅保存在受控服务器目录，不打印内容。
2. 只读确认线上代码与 B3 基线一致，检查两项迁移所需字段/表是否已存在，并聚合统计旧 `two_factor_enabled=1` 行。若有异常旧标记，停止上线并人工分析。
3. 在隔离数据库按顺序执行 `20260915_b4_token_version.sql` 和 `20260915_b4_totp.sql`，验证现有用户表兼容、新用户注册、登录、会话撤销和 TOTP/恢复码全流程。
4. 在维护窗口对生产库按核查结果执行上述加法迁移，不执行 DROP、TRUNCATE、DELETE，也不批量清除 2FA 标记或密钥。
5. 部署 B4 代码并重启单实例 PM2，验证健康检查、静态资源、模拟认证。旧 JWT 会被拒绝，现有用户需重新登录一次。
6. 只有在上述验收通过后开放账号绑定；用户必须离线保存恢复码。6 元支付宝真实交易及相关回归，等支付宝限额调整完成再验收。

## 回滚边界

- 新增列和恢复码表保留，不执行 `DROP COLUMN`、`DROP TABLE` 或不可逆数据清理。
- 回滚到 B3 后，B3 代码不会检查 `token_version`；需先暂停认证入口并评估旧 JWT 风险，不可直接无审核回滚。
- 若已有用户启用二次认证，不能直接回滚到 B3；B3 登录不会校验验证码，会造成认证降级。应优先修复 B4 或暂停认证入口，再制定受控回滚。
