# B6.1 租号账号审核闭环

这是 B6 的第一小批：修复租号账号待审核时无管理入口及所有者自助上架的
权限漏洞。它不改价格、支付、退款、租号订单结算逻辑或数据库结构。B6 的
其他模块化、索引、上传和性能工作须逐批实施。

## 发布前只读基线（2026-09-16）

- 线上 B5 核心 `server.js`、`script.js`、`index.html` 统一 LF 后均与仓库
  `fcc2ad8` 的 Git blob 哈希一致，没有真实业务代码漂移。
- 阿里云 `rental_accounts.status` 为 `pending/active/suspended` 枚举；目前
  待审核账号 2 个，租号订单 0 个。这些申请不会在本批自动通过或驳回。
- B5 `operation_audit` 已在生产库；B6.1 审核、下架及重新审核申请都与
  账号状态变更同事务记录审计。审计失败会回滚状态。
- 业主已自行完成 6 元真实支付宝交易验证；B6.1 不修改相关配置或代码。

## 账号状态与操作

- 出租方：`active → suspended` 可以自行下架；`suspended → pending` 可以
  申请重新审核。不能自行将 `pending/suspended` 改为 `active`。
- 管理员：在“主菜单 → 管理面板 → 租号审核”按资料和截图审核。
  `pending → active/suspended`；可将 `active → suspended` 强制下架，或
  在重新核实后将 `suspended → active`。审核参数必须是布尔值，重复或
  冲突状态返回 409，不会静默改写。
- 管理员审核账号只改变公开出租账号可见性，不表示租号订单已付款。
  租号订单的收款、退款与争议仍由同一租号审核页下方的 B5 人工流程处理。

## 部署与验收

1. 核查 Git 和线上哈希、阿里云真实状态及 PM2；先制作新鲜受限的生产
   数据库与应用文件备份，不展示 `.env` 或密钥内容。
2. 在隔离发布目录运行全部合成凭据测试、后端/前台语法检查；仅部署本批
   明确文件，不覆盖线上 `.env`、支付宝密钥、上传目录或依赖目录。
3. 重启单实例 PM2，验证健康接口、租号公开列表及管理员接口匿名 401。
   不通过生产 SQL 直接修改那 2 个待审核账号。
4. 业主使用管理员账户打开租号审核页，逐条核对账号资料与截图后自行
   审核；用出租方账户刷新“我的出租”，再从另一个账户查看租号大厅。
5. 如果账号已上架，再分别测试出租方下架、申请重新审核和管理员重新
   通过；不要把小额真实支付测试与账号审核权限测试混在同一订单里。

## 回滚

- 若 B6.1 页面或 API 出错，从新鲜应用备份仅恢复本批代码文件并重启
  PM2；不要删除 B5 表、审核审计或用户数据。若已经有管理员审核动作，
  先评估这些动作的业务影响，不能自动反向改写账号状态。
