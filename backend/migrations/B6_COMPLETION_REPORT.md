# B6 完成范围与验证

B6 采用小批次完成，没有将整个项目一次性重构：

- B6.1/B6.2：补齐租号管理员审核页、权限状态机、审计、分页，并修复生产
  MySQL 对分页 DOUBLE 参数返回 1210 的问题。
- B6.3：租号账号可恢复软删除，阻止有进行中租单的删除；新增账号可见性、
  出租方列表及租单占用检测索引。此项包含加法生产迁移，须先迁移再部署代码。
- B6.4：前端租号 API、状态和截图文件名验证集中到 `rental-client.js`；大厅
  使用 5 秒短缓存及并发去重，审核、上下架、删除和恢复会失效缓存。
- B6.5：新出租截图使用异步流、5MB 上限、PNG/JPEG 文件头验证、临时文件
  和原子改名；旧 Base64 请求保留兼容。支付截图业务流程未在重构中改写。
- B6.6：租号账号、审核和截图路由从 `server.js` 拆到依赖注入模块；租号订单
  支付、退款和结算仍保留原位，作为下一阶段独立拆分对象。

清理了租号模块中的重复截图解析、直接 fetch、同步文件写入、调试日志和入口
重复路由；统一使用入口的 crypto 实例。每批都有回归测试和发布/回滚说明。

## 尚未纳入 B6 的事项

- 上传文件仍保存在本机受限目录，没有迁往对象存储；现有规模下先采用安全的
  异步流方案。迁移对象存储需要新增云端凭据、生命周期和备份策略，不能在未
  授权下代替本地存储。
- 付款截图、富文本图片的旧 Base64 接口没有借重构改写，避免改变已验证的支付
  流程；需要另立支付/内容上传批次并做真实回归。
- B7 的错误体验、可访问性、移动端、时间线、多语言/2FA 产品决策及主题 CSS
  不属于 B6，未在本批顺带修改。

生产完成标准：B6.3 加法迁移计划和备份通过，迁移应用并验证字段/索引；随后
在隔离目录通过全量测试，按白名单部署 B6 集成代码、重启 PM2 并完成健康、
权限、静态文件、管理员审核、软删除/恢复及 PNG/JPEG 上传验收。不得自动审核
账号、创建真实租单或修改支付宝配置。
