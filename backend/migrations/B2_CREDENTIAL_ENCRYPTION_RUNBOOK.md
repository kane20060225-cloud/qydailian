# B2 游戏凭据加密迁移手册

本手册只描述审批后的操作顺序。不要在未备份、未安排维护窗口时执行生产迁移。

## 前置条件

1. 保留可恢复的数据库和应用备份。
2. 在服务器内部生成独立的 32 字节随机密钥，并以标准 Base64 写入 `DATA_ENCRYPTION_KEY`。不得复用 JWT 或支付宝密钥。
3. 将 `20260914_b2_expand_sensitive_fields.sql` 交由有权限的数据库管理员审核并执行。
4. 不部署依赖新字段容量的 B2 服务代码，直到字段扩容成功。

## 推荐顺序

1. 在维护窗口将站点切为禁止创建新订单，避免迁移期间并发写入。
2. 执行字段扩容 SQL；该 SQL 不删除表或数据。
3. 使用 `node scripts/encrypt-legacy-credentials.js --report` 仅统计待迁移数量。脚本不会输出字段值。
4. 设置一次性确认变量后执行 `--apply`。脚本在事务中加密旧数据，并通过原值条件更新检测并发变化。
5. 再次执行 `--report`，确认待加密数量为零。
6. 部署 B2 服务代码并运行登录、创建订单、订单详情、管理员订单和打手订单检查。
7. 确认服务稳定后恢复创建订单。

## 回滚边界

- 应用代码可以回滚，但旧代码无法理解加密后的字段，不能单独回滚应用。
- 数据解密回滚需要专门的、经审核的反向脚本；不得直接用 SQL 猜测或截断密文。
- `DATA_ENCRYPTION_KEY` 丢失会导致数据不可恢复，必须使用独立的安全备份保存。
