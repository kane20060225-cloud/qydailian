# B9 统一订单与充值记录

订单中心仅汇总读取代练、租号、充值、积分商城兑换与三方订单。原业务表仍为状态来源，普通用户仅可查看自己购买或参与的订单；三方订单仅管理员及创建该订单的打手可查看。管理员默认待办，支持类型、状态、订单/交易号/用户/内容、日期、支付渠道和归档筛选。每页 25 条，导出最多 5000 条，并转义 CSV 公式。

充值先创建支付订单、6 元价格和 10000 券数量快照，再在原订单打开支付宝支付。通知与主动查询共用已校验金额、签名、商户身份和交易号的入账事务。支付订单转为 paid、用户加券和唯一到账流水一起提交；失败回滚，记录平台已成功用于显示到账处理中，重试不重复发放。已 paid 但没有对应流水的历史订单显示待核对，不自动补发。页面支付返回参数不能改变余额或订单状态。

## 发布

1. 备份现有数据库及站点。
2. 在独立目录运行 `npm test`；只复用 node_modules，不加载生产 .env。
3. 明确连接目标库后运行 `npm run migration:b9:order-center -- --plan`。
4. 审核计划，仅允许新增充值工作流、归档元数据、订单操作记录三张表，运行 `npm run migration:b9:order-center -- --apply --confirm=B9-ORDER-CENTER-ADDITIVE-MIGRATION`。
5. 发布 backend/server.js、新增 lib/routes 模块及前端文件，再重启后端，检查健康接口和静态资源版本。

迁移不改动历史订单或余额。生产故障时恢复备份中的运行文件，保留新增元数据表和迁移版本；不要删除已产生的新订单、到账流水或操作记录。

## 验证

`scripts/verify-order-center-isolated.js --database=qydailian_b9_test_<suffix>` 只允许显式指定且没有用户的隔离数据库，使用生产表结构的空副本和模拟支付结果验证真实 MySQL、详情权限、分页、归档、导出、到账失败回滚和重复通知。

`scripts/verify-order-center-browser.js` 使用 Playwright、本地静态站点和模拟 API，验证 1440×1000 与 390×844；可通过 `BROWSER_CHANNEL=msedge` 使用系统浏览器。该脚本不打开真实支付页面，不依赖生产账号。

管理员人工确认收款和到账重试必须填写说明；充值重试仍查询支付宝，不能直接指定已付款或直接加券。代练确认付款后待派单，放入大厅只允许已付款、待接单且未分配订单。旧的直接覆盖状态和删除订单接口返回 409，最终订单通过归档保留历史。
