# B28 订单关联人工客服与权限管理

本版沿用普通发送接口、MySQL 持久化和 SSE 实时同步。新增 `support` 客服角色；仅客服和管理员可以访问客服工作台。普通用户和打手只能查看自己发起的会话。角色仍为单选，修改为客服会替换原角色。

## 用户和客服入口

- 全站右下角“联系客服”；登录后可留言。自己的订单详情提供“联系客服”，自动复用该订单的咨询会话。
- 用户菜单里的“客服工作台”仅向客服和管理员显示。后台接口每次验证数据库中的权限。
- 聊天支持文字、PNG/JPEG 截图（5MB）、历史分页、未读数、断线自动重连。重连按消息 ID 补齐所有遗漏分页。
- 发送失败保留草稿和相同消息编号；重试不会重复生成消息、图片或通知。“放弃重试”不撤回可能已经送达的消息。
- 客服列表默认显示待处理，先排列仍未回复的咨询，再按等待时间排序。读取消息不会解除等待；回复后解除等待，标记已解决后用户再次留言会重新进入待处理。
- 手机端聊天占满屏幕，通过 `visualViewport` 跟随键盘可用高度；空间不足时缩短顶部和输入区。
- 工作台“离站提醒与服务时间”中，管理员可设置每日服务时段（北京时间）。初始服务时段未确认，只展示“可以留言”，不宣称在线。

## 隐私与权限

关联订单仅返回订单号、项目、金额和业务状态。采用允许字段列表，不读取游戏账户密码、付款参考号或联系人。第三方订单的自由填写内容不带入摘要。

聊天图片存储在 `backend/private-support/`，没有静态公开目录。图片请求带登录认证，并校验会话归属或客服权限；接口不返回磁盘文件名。退出登录时清空会话内容和图片 Blob。请把该私有目录纳入备份，避免发布时覆盖或清空。

权限管理默认搜索用户名或精确用户 ID，支持角色筛选；“浏览全部用户”保留逐页查找，每页20人。选中用户后显示当前角色及新角色说明，再保存。变更有审计记录，旧登录令牌失效；防止覆盖已变化的角色、移除自己的管理员权限或移除最后一位管理员。

## 上线步骤

1. 备份数据库，确认已有 B12 通知相关表和当前 B27 订单结构。
2. 在后端运行 `node scripts/migrate-b28-support.js --plan` 查看增量 SQL；确认数据库后运行 `node scripts/migrate-b28-support.js --apply`。只新增客服表，不修改订单、余额或既有用户角色。MySQL DDL 不支持事务回滚，可重复执行补齐表。
3. 一并发布新增模块和本版修改的前后端文件，重启后端。前端入口位于 `public/index.html`；新后端路由位于 `backend/routes/customer-support.js` 和 `backend/routes/user-permissions.js`。
4. 管理员在“权限管理”搜索客服账号，将角色设为客服。该账号重新登录后进入工作台；配置实际服务时段。
5. 按下方步骤验证企业微信手机提醒，再开始接待。

## 企业微信离站提醒验收

沿用现有企业微信自建应用、账号 OAuth 绑定和持久化重试队列。客服咨询提醒独立于接单身份、打手上下线和订单通知偏好；企业微信发送开关仍然有效。收到的是简短提醒和会话链接，不包含聊天原文、截图或游戏资料。

管理员需将客服成员加入自建应用可见范围，在网站通知设置中核对 CorpID、AgentID、Secret、授权域名、可信 IP 和发送开关。客服在工作台绑定自己的企业微信账号；提示“未就绪”时检查绑定及企业微信发送偏好。

工作台展示就绪成员数量和当前账号最近10条发送结果。点击“发送测试提醒给我”，然后刷新发送状态。未绑定或应用未启用时，只生成站内通知，不会创建企业微信发送任务；界面的未就绪提示不能替代配置。

必须在真实手机上确认收到测试通知，再关闭后台浏览器，用另一用户提交新咨询，确认手机收到并能打开对应会话。接口显示“已发送”只代表企业微信接受请求，不能证明手机通知权限已经打开。测试消息的链接打开提醒设置页。网络失败使用持久化指数退避重试，最多5次；失败代码在工作台显示。角色被撤销时，未发出的客服咨询提醒会跳过。
